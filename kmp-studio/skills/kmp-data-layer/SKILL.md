# KMP data layer: Ktor, Room, DataStore, Koin

All versions come from `.studio/research.md`. KSP's version must match the Kotlin version.

## Ktor client
- `commonMain`: `ktor-client-core`, `ktor-client-content-negotiation`, `ktor-serialization-kotlinx-json`, `ktor-client-logging` (debug only).
- Engines: `ktor-client-okhttp` in `androidMain`, `ktor-client-darwin` in `iosMain`. Provide the engine through DI; do not use `expect`/`actual` for it.
- One `HttpClient` for the app, configured once:
```kotlin
fun createHttpClient(engine: HttpClientEngine) = HttpClient(engine) {
    expectSuccess = true
    install(ContentNegotiation) { json(Json { ignoreUnknownKeys = true; explicitNulls = false }) }
    install(HttpTimeout) { requestTimeoutMillis = 30_000; connectTimeoutMillis = 15_000 }
    defaultRequest { url(BASE_URL); contentType(ContentType.Application.Json) }
}
```
- DTOs are `@Serializable`, live in `data/remote`, and are mapped to domain models. Nullable or defaulted fields for anything the server might omit.
- Wrap every call in one helper that maps `ResponseException`, IO and serialization failures to `AppError` and rethrows `CancellationException`.
- HTTPS only. API keys come from build config, not source; a key shipped in a client is public, so anything sensitive belongs behind a backend.

## Room (KMP)
- Dependencies: `androidx.room:room-runtime` and `androidx.sqlite:sqlite-bundled` in `commonMain`; the Room Gradle plugin with a schema directory; the compiler added through KSP **for each target** (`kspAndroid`, `kspIosArm64`, `kspIosSimulatorArm64`, plus `kspCommonMainMetadata` only if the setup in use requires it).
- Database in `commonMain`:
```kotlin
@Database(entities = [NoteEntity::class], version = 1)
@ConstructedBy(AppDatabaseConstructor::class)
abstract class AppDatabase : RoomDatabase() { abstract fun noteDao(): NoteDao }

@Suppress("NO_ACTUAL_FOR_EXPECT")
expect object AppDatabaseConstructor : RoomDatabaseConstructor<AppDatabase> { override fun initialize(): AppDatabase }
```
  The `actual` is generated by the compiler; do not write it.
- A platform builder per target returns `RoomDatabase.Builder<AppDatabase>`: Android uses `context.getDatabasePath(name)`, iOS uses the documents directory from `NSFileManager`. Common code finishes it:
```kotlin
builder.setDriver(BundledSQLiteDriver()).setQueryCoroutineContext(Dispatchers.IO).build()
```
- DAO functions are `suspend` or return `Flow`. Blocking DAO functions do not compile for iOS.
- Entities stay in `data/local`; map to domain models. Every schema change bumps `version` and ships a migration; export schemas and commit them.

## DataStore (preferences)
- `androidx.datastore:datastore-preferences` in `commonMain`. Create it once with `PreferenceDataStoreFactory.createWithPath { path.toPath() }`, where the platform supplies the file path (Android `filesDir`, iOS documents directory). The file name must end in `.preferences_pb`.
- Exactly one instance per file for the whole process; provide it as a DI singleton.
- Expose typed flows from a small settings repository; keys are private to it.
- For small secrets use the platform keystore or keychain behind an interface, not DataStore.

## Koin
- `koin-core` in `commonMain`, `koin-android` in `androidMain`, `koin-compose` and `koin-compose-viewmodel` for Compose.
- Modules: one per feature plus `coreModule`, and an `expect val platformModule: Module` (or a module passed in at startup) for platform implementations.
```kotlin
val notesModule = module {
    singleOf(::NotesRepositoryImpl) bind NotesRepository::class
    factoryOf(::ObserveNotes)
    viewModelOf(::NotesViewModel)
}
fun initKoin(config: KoinAppDeclaration? = null) = startKoin { config?.invoke(this); modules(coreModule, platformModule, notesModule) }
```
- Start Koin in the Android `Application` (`initKoin { androidContext(this@App) }`) and from Swift before the first view (`KoinInitKt.doInitKoin(...)` or a wrapper function with a plain name).
- In composables use `koinViewModel()`; pass arguments with `parametersOf`. Do not call `get()` or `inject()` inside screens.
- Singletons for clients, databases and repositories; factories for use cases; `viewModelOf` for ViewModels.
- Swift-implemented services (ads, billing) are passed into `initKoin` as parameters and registered with `single { it }`.

## Offline-first repository shape
The database is the source of truth. The repository exposes a `Flow` from the DAO and a `suspend fun refresh()` that fetches, maps and upserts. The UI observes the flow; refresh failures surface as an error state while cached data stays visible.

## Review checklist
- [ ] One `HttpClient`, one database, one DataStore instance, all provided by DI.
- [ ] No DTO or entity leaves the data layer.
- [ ] KSP is configured for every target that is built.
- [ ] Every DAO function is `suspend` or returns `Flow`.
- [ ] Schema version bumps come with migrations.
